# Paseo LaTeX client

Keep the personal client on the `paseo-latex` branch. The `upstream` remote points to
`https://github.com/getpaseo/paseo.git`. Merge upstream releases into this branch so
the chat rendering and personal app identity remain in its history.

## Build from a clean checkout

The personal source repository is `https://github.com/TwiceDrop/paseo-latex.git`.
Its default `main` branch includes the personal patches; `paseo-latex` is the
maintenance branch. Use Node.js 22.20 or a newer Node 22 release and npm. Linux
build machines also need the native compiler prerequisites required by the target.

```sh
git clone https://github.com/TwiceDrop/paseo-latex.git
cd paseo-latex
npm ci --ignore-scripts --no-audit --no-fund
npm run postinstall
npm run latex:web
```

`latex:web` builds the workspace dependencies, regenerates the math and document
resources, then exports `packages/app/dist`. It works on Linux cloud build
machines and Windows without files from the original developer's computer.
It needs network access for the locked npm dependencies. It does not need host
credentials, an Expo account, Android signing keys, `.dev/`, or `artifacts/`.

For editing and typechecking without exporting the app, run `npm run latex:prepare`
instead of `latex:web`, then `npm run typecheck --workspace=@getpaseo/app`.
Protocol validators and workspace `dist` directories are generated by these
builds, so keep them ignored. Keep the checked-in document runtime, math assets,
native download module, config plugins and every tracked vendor patch.

The **LaTeX Source Build** Actions workflow checks a fresh Linux checkout,
compiles the app plus bundled host/CLI, and runs the document and real math
regressions. It uploads the web export as a build artifact. Upstream workflows
are restricted to `getpaseo/paseo`; they do not deploy official services or publish
releases from this personal repository.

For the independent Windows installer, use a Windows machine and
`npm run windows:latex -- --revision 4`, or manually run **LaTeX Source Build**
with its Windows option enabled. Linux cloud environments cannot directly run
the Windows-only installer script. Increase the revision after each delivery.

**LaTeX Source Build** can also build the personal Android ARM64 APK when its
Android option is enabled. Set the repository Actions secrets
`PASEO_LATEX_KEYSTORE_BASE64` to the base64-encoded existing `release.keystore`
and `PASEO_LATEX_CREDENTIALS_JSON` to the existing `credentials.json`. Keep these
values in GitHub Secrets, outside source and build artifacts. The job restores
the original signing files in the runner's temporary directory, verifies the
signed APK and its `sh.paseo.latex` identity, then removes the signing files.
Both build options share the revision input; a new upstream version starts at 1.
Successful builds are available as Actions artifacts; they do not create a release.

The workflow's `publish_only` mode publishes an existing draft personal release.
It requires the release tag, the successful Windows build run ID, and a temporary
`build-assets/<release-tag>` branch containing only APK parts and `manifest.json`.
The manifest binds both installers' SHA-256 hashes and the Android signing
certificate to the tagged source commit. The publisher checks the source and
Windows jobs, reconstructs and verifies the APK, then uploads both installers and
`SHA256SUMS.txt` before publishing. Remove the temporary assets branch afterward.
Signing keys and credentials must never enter that branch.

For Android, install JDK 21, the Android SDK/NDK required by Expo 57 / RN 0.86,
and restore the **existing** personal signing directory outside the checkout.
After installing dependencies with `--ignore-scripts`, run
`npm rebuild @shopify/react-native-skia --foreground-scripts` to prepare its
locked native libraries before building.
Set `PASEO_LATEX_SIGNING_DIR` to that directory when it is not the default sibling
path. Then run `npm run android:latex -- --arch arm64-v8a --low-memory`.
The repository deliberately contains no release private key or password. A cloud
machine cannot produce an upgrade signed with the existing certificate until
those signing files are supplied securely; do not generate a replacement key.

When updating upstream in a fresh clone, add the official remote first:

```sh
git remote add upstream https://github.com/getpaseo/paseo.git
git remote set-url --push upstream DISABLED
git switch paseo-latex
```

The current source includes the PDF/slide width and unchanged-document caching
fixes made after the Windows 0.13.0-r3 delivery. Local `artifacts/` logs describe
historical builds and are not cloud validation evidence. Use the Actions result
for the exact commit being built.

The Android app is **Paseo LaTeX**, package **`sh.paseo.latex`**. It installs alongside
the official app. Each app keeps its own settings and host credentials; pair the
personal app with your existing host. Both apps accept official `paseo://` pairing
links, so Android can ask which app should open a link. Scan or paste the pairing
link inside the app you want to use.

This client uses the existing daemon protocol. Keep the official daemon if you
want. Check your actual host version when validating a new upstream release;
[protocol compatibility](protocol-compatibility.md) does not promise every new
feature on an older daemon.

## Android file downloads

Open a file link in chat, then choose **Download** in the file preview toolbar.
The file explorer's long-press menu uses the same download action. Android opens
its system **Save as** dialog after receiving the file; choose a location to finish.
Cancelling that dialog does not mark the file as saved.

Native downloads use the daemon's existing binary file frames on the authenticated
connection, including encrypted relay connections. They do not require an exposed
HTTP port or a daemon upgrade. Keep the streaming destination in the client:
buffering a whole APK through `readFile()` duplicates large byte arrays in memory.
The Android document picker lives in `modules/paseo-file-download`; using
`ACTION_CREATE_DOCUMENT` permits saving to Downloads without broad storage access.

## Document previews

Open a file from Explorer or a chat file link. DOCX documents render paragraphs,
tables and page breaks; PPTX presentations have page and zoom controls. XLSX,
XLS and CSV files have a worksheet selector and pages of up to 200 rows / 2,000
cells. Wide sheets use fewer rows per page. PDF files render
one page at a time with zoom controls. TXT, LOG and configuration text recognize
UTF-8, UTF-16 BOMs and GB18030. Existing code, Markdown, HTML and image views
keep their own renderers.

From 0.13, document previews participate in the file panel **Open with** selector.
Plugin file panels remain selectable. The file tab's download action is available
even when a file has no preview or a plugin supplies its panel.

The document viewer reads at most 32 MB over the existing authenticated session.
It runs in an isolated iframe or native WebView with its parsers, PDF CMaps and
standard fonts bundled locally. It does not upload documents to an Office service.
Old binary DOC/PPT documents must be saved as DOCX/PPTX or downloaded to open in
Office. Excel previews show cached values; they do not calculate formulas or
render embedded charts, and show at most 200 columns. Complex Office layout can
differ from the desktop applications.

Retained document panes reuse the fetched bytes for 30 seconds during rapid tab
or workspace switches. Reopening a pane revalidates immediately; returning after
30 seconds also revalidates. An unchanged response retains the existing byte array,
so revalidation does not rebuild the viewer HTML. Hidden panes do not initiate reads. Native workspace
retention remains limited to one workspace to bound memory and preserve Fabric
ownership. PDF backing canvases are capped at 4,194,304 pixels and 8,192 pixels per
side (about 16 MiB of RGBA storage); CSS zoom remains available, with reduced
raster resolution on very large pages. Binary decoding writes directly into a
typed array instead of allocating a temporary array for every character.

PDF and slide previews refit after pane width changes, including returning from a
hidden workspace, while preserving the selected page and zoom. Slide zoom reuses
the rendered SVG. PDF resizing waits for the active render to finish before using
the same canvas again.

After changing the viewer runtime or parser dependencies, run
`npm run build:document-preview --workspace=@getpaseo/app`. The generated viewer
is checked in, and `android:latex` rebuilds it before packaging. Keep the ZIP
expansion and byte-count limits at the file boundary. Disable DOCX altChunks and
keep frame navigation and external resources blocked; document content must not
gain access to the app or its host credentials.

## Markdown engine updates

From 0.12, chat uses Enriched Markdown's native math renderer on Android and
KaTeX MathML on the web. Enable both the package's `enriched-markdown.enableMath`
build setting and the renderer's `latexMath` flag. Keep TeX opaque while adapting
HTML, images and file links, and keep a multiline formula inside one streaming
text view. Otherwise an engine update can silently alter TeX or split its delimiters.

The Android build restores the pinned code-highlighting grammar sources after
an install with `--ignore-scripts`; it does not download iOS frameworks.
The vendor patch applies the engine's horizontal-block gesture handling to math
as well as code and tables, so formula drags do not accidentally open sidebars.

## Collapsed sidebar projects

Press a project heading to move the whole group into **Collapsed projects** above
the sidebar footer. Press its name there to restore it in its previous order.
This reuses the device's existing collapsed-project preference; it sends no
archive, remove, or lifecycle command to the host. Project filters still apply
to the bottom section, so clear them to find a filtered-out project.

## Loading and navigation

The floating header and pane content have separate, non-collapsible native hosts
with explicit stacking. Chat loading overlays stay below the header, so sidebar
and tab controls remain reachable while history catches up. Passive initial
loaders do not claim touches.

Agent lookup only runs in a visible pane with a connection. A failed lookup
remains on its retry view instead of immediately resubmitting. Hiding the pane,
changing the agent/host, or disconnecting invalidates its outstanding callback;
a late response cannot overwrite the newer view. This does not cancel shared
transport requests needed by other consumers or restart the host.

## Personal signing

Set `JAVA_HOME` to your JDK 21 directory. On this Windows machine:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
npm run latex:keygen
```

The command creates a persistent personal key in the sibling directory
`../paseo-latex-signing/`, outside this Git checkout. Back up **both**
`release.keystore` and `credentials.json`. Future APK upgrades require the same
key. Running the command again reuses it. `PASEO_LATEX_SIGNING_DIR` can select
another persistent location.

The personal variant does not use the official Expo account, EAS project or
Firebase configuration. Push notifications need your own Expo project's UUID in
`PASEO_LATEX_EAS_PROJECT_ID` and the Android Firebase file for `sh.paseo.latex` in
`GOOGLE_SERVICES_FILE_LATEX`. Without these, use the official app for push
notifications; host pairing and chat remain available in the personal app.

## Build an APK

Install the [Android toolchain](android.md#prerequisites-local-dev), then run from
the repository root:

```powershell
npm run android:latex
```

On Windows, the signing plugin places CMake's staging files in `.dev/cxx` and
limits object paths to 240 characters. This keeps the new renderer's generated
C++ paths within Ninja's Windows path limit even in this nested checkout.

For a phone-only ARM64 build:

```powershell
npm run android:latex -- --arch arm64-v8a
```

To test the same APK on an ARM64 phone and an x86_64 emulator, include both ABIs:

```powershell
npm run android:latex -- --arch arm64-v8a,x86_64
```

If the build exhausts local memory, add `--low-memory`. This uses one Gradle and
Metro worker, limits the Gradle heap to 2 GB, and uses Hermes `-Og` instead of
`-O`. Close test emulators while compiling. It still builds a signed release APK,
with fewer compiler optimizations:

```powershell
npm run android:latex -- --arch arm64-v8a --low-memory
```

The result is `artifacts/paseo-latex-<upstream-version>-r<revision>.apk`, signed
with the personal key. `--prepare-only` regenerates the Android project and
signing configuration without compiling or installing an APK.

For another build of the same upstream version, increase `--revision`:

```powershell
npm run android:latex -- --arch arm64-v8a --revision 2
```

Revisions range from 1 through 99. A newer upstream version starts at revision 1.
Its Android version code exceeds the previous upstream version's revisions.

## Build a Windows installer

Run `npm run windows:latex` on Windows for an x64 NSIS installer. It includes the
current renderer changes and writes to
`artifacts/windows-latex-<version>-r<revision>/`. Use `-- --revision 2` for another
delivery of the same upstream version; the build refuses to overwrite an existing
installer.

Install **Paseo LaTeX** alongside official Paseo. The installer lets you choose a
separate directory. Its app ID, uninstall registration, executable and shortcuts
are independent. It leaves the official `paseo:` URL handler registered to Paseo.
Settings and browser storage live under `%APPDATA%/Paseo LaTeX`; its built-in host
uses the `daemon` subdirectory and a free loopback port. Add the original host by
IP/Tailscale to use its existing workspaces. The optional CLI installs as
`paseo-latex`, leaving the official `paseo` command in place.

Official automatic updates are disabled for this distribution. Rebuild the
personal installer after merging upstream and increase its revision. The runtime
version stays equal to the bundled host version; the Windows file version carries
the revision so host management does not repeatedly restart on a version mismatch.

This build runs compilers sequentially and uses one Metro worker. Node heaps are
limited to 1.5 GB, with 2 GB for the renderer export. It checks for 3 GB of free
memory before exporting, 2 GB before other steps, and stops its own build process
tree if free memory falls below 1 GB. Low-memory server
builds use the repository's native TypeScript compiler with a 1 GB Go heap target
and two CPUs. Normal builds keep the upstream compiler. Do not run emulators or
heavy tests alongside packaging. Windows signing requires a separate code-signing
certificate; the personal Android keystore cannot sign this installer.

The personal installer backports electron-builder's bounded UserProgramFiles path
copy through a versioned vendor patch. Keep that patch while the pinned
builder has the legacy fixed-width read: both 0.12 and 0.13 installers reproduced
an intermittent `System.dll` access violation on this Windows machine. It must
preserve existing install locations and the user's explicit directory selection.

After an interrupted renderer/package step, `-- --resume` reuses the already-built
dependencies. Only use it while those source files are unchanged.
For a desktop-wrapper-only change, `-- --package-only` also reuses the exported
renderer. Rebuild the renderer whenever app source changes.

## Merge an upstream release

Commit local changes before updating. Select a released tag explicitly:

```powershell
npm run latex:update -- --ref v0.13.2
```

Replace the example tag with the release you want. The command fetches upstream,
merges the selected commit, installs dependencies, regenerates math fonts and
runs client typecheck, lint and targeted unit tests. It stops on a merge conflict
or failed check. Resolve and commit a conflict on `paseo-latex`, then rerun the
same command. Commit any regenerated assets before the next update.

To inspect an already fetched target without merging:

```powershell
npm run latex:update -- --ref upstream/main --dry-run
```

After an update, run the existing browser checks and build a test APK:

```powershell
npm run test:browser --workspace=@getpaseo/app -- src/components/markdown/math/enriched.browser.test.tsx src/components/floating-header/index.browser.test.tsx src/assistant-selection-copy/content.browser.test.ts --bail=1
npm run android:latex -- --arch arm64-v8a
```

Check formula rendering, host pairing and chat on the device before using the
new APK. These commands keep the work local; configure your own Git remote or
release hosting separately if you want to distribute builds.
